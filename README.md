# Домены .xd

Две части:

1. **app.py** — панель-реестр (Flask). Люди получают name.xd и указывают, куда он ведёт (ip:порт или https-адрес).
   Запуск: `pip install -r requirements.txt && python app.py`. На Railway/Render работает как есть (Procfile).
   Данные лежат в domains.json (на Railway подключи Volume и задай XD_DATA=/data/domains.json).
2. **xd.py** + **install.sh** — Termux-клиент. Локальный прокси 127.0.0.1:8118 берёт список доменов из панели
   и сам ведёт name.xd на нужный адрес. Только остальной трафик не трогает (PAC-файл).

## Пользователь
    bash install.sh   # адрес панели по умолчанию 100.189.67.15:4403
    xd start
Wi-Fi → Прокси → Автонастройка → http://127.0.0.1:8118/proxy.pac
Открывать: http://name.xd

## Ограничения
- Только HTTP (для .xd нельзя выпустить HTTPS-сертификат).
- Работает на устройствах с установленным клиентом.
- Прокси по PAC настраивается для Wi-Fi; мобильный интернет Android так не умеет.

## Хостинг сайтов на сервере 100.189.67.15:4403
- Запуск сервера: `pip install flask && PORT=4403 python app.py` (порт должен быть открыт снаружи).
- Сайт `имя` открывается у всех по `http://100.189.67.15:4403/имя/` — без установки.
- `http://имя.xd` — красивый адрес для тех, у кого стоит клиент (клиент добавляет X-Forwarded-Host, сервер отдаёт нужный сайт).
- Переменные: XD_PUBLIC (публичный адрес сервера), XD_DATA (domains.json), XD_SITES (папка сайтов).
- Сайты изолированы CSP sandbox: свой localStorage/cookies у них не работают, зато они не могут украсть ключи из панели.

## Подключение без установки (прокси сервера)
- Страница `http://100.189.67.15:4403/connect` — инструкция + проверка.
- Человек один раз вставляет в Wi-Fi → Прокси → Автонастройка адрес `http://100.189.67.15:4403/proxy.pac`.
- PAC отправляет на наш сервер только `*.xd`, всё остальное идёт напрямую. Сервер не является открытым прокси: чужие сайты он не пересылает.
- Сайты, открытые по пути `/имя/`, показывают снизу плашку «Подключить» со ссылкой на /connect.
- Termux-клиент остаётся как запасной вариант.
